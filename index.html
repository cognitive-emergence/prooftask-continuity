ProofTask continuity mirror

This directory lets anyone verify a stored ProofTask result record without contacting ProofTask. It holds the offline verifier, the issuer public keys (current and historical) and the key history. Nothing here needs a network connection.

Built 2026-11-23T03:13:33.902Z from https://prooftask.com. Release d4e7492f338536d0f11c0dd29a30643e9060e13a. Verifier SHA-256: 6f5bcb7f3a7ea7f1ed91558e89e50d7cdb150bc2cabb5927241aa7f346ab1f4b

1. Check this mirror

Every file is listed with its SHA-256 in manifest.json and SHA256SUMS. In this directory, run:

shasum -a 256 -c SHA256SUMS

Then compare the issuer key fingerprints below with a source you trust independently of this mirror: the fingerprint shown on a record you received, the key pins committed in the ProofTask source repository (keys/operator-issuers.json is a copy), or another mirror. A mirror is only as trustworthy as that comparison.

2. Verify a stored record

You need Node.js 22 or later and the record file you saved (for example prooftask-result-record-<id>.json or a Conformity Package). From this directory, run:

node verifier/verify-conformity.mjs /path/to/prooftask-result-record-ID.json keys/prooftask-trust-bundle.json --text
  • The verdict is one of VERIFIED_WITH_LIMITATIONS, PARTIAL_DISCLOSURE, INDETERMINATE, INVALID. Exit status 0 means verified (read the listed limits), 1 means invalid and 3 means it cannot be determined.
  • To check as of a past time, add --at=2026-11-21T00:00:00.000Z.
  • If the key that signed your record is no longer in the current trust bundle, find its key ID in keys/key-history.json and pass the historical trust bundle it names (in history/trust-bundles/) instead of keys/prooftask-trust-bundle.json.
  • A record signed by a ProofTask production key that is pinned in the verifier also verifies without the second argument: node verifier/verify-conformity.mjs RECORD --text
  • Without a terminal, open verifier/prooftask-buyer-record-checker.html (if present) in a browser and select the record and the trust bundle.

What this cannot tell you: the current status of a result (a signed status statement comes from the running service; without one, current status is reported as unknown), whether original files you do not supply match, or a company’s authority beyond what you approve yourself. The signed history and signatures are checked in full.
